# 由桌面承载查验界面并保留独立业务更新

状态：accepted，2026-11-02。用户已最终确认方案并授权写入 [Issue #6](https://github.com/ChenWingYan/Cic_virtual_desktop/issues/6) 后开发。独立业务产物的主屏离屏承载原型已实现；生产渲染结论仍须真实输入法、视频性能和目标设备证据。

沿用 [ADR 0001](0001-managed-content-and-public-contracts.md) 的受管理内容边界，业务代码继续留在独立工程中维护和构建，用户将运行产物放入指定目录，虚拟桌面按配置接入。不得将业务源码复制或合并进桌面工程，也不应要求桌面构建时依赖业务源码。

比较过启动目录中的独立业务 EXE，以及由桌面 Electron 加载业务页面并运行独立后端。采用后者完成主屏接入验证，使业务内容进入统一方向、比例和输入校正；前者启动后仍为独立窗口，不能自动获得桌面的显示校正。离屏 PNG 帧传输是当前原型实现，不代表已确定生产渲染路线。

用户已确认允许在独立业务工程中增加供虚拟桌面使用的接入入口，并随运行产物发布；原业务 EXE 继续支持独立运行。业务相关适配随业务组件维护和更新，桌面只维护通用加载能力。无需将业务源码合入桌面，也不在桌面构建期间构建业务工程。

查验组件保留独立更新能力，不要求每次业务更新都重新发布虚拟桌面；双方需要明确兼容接口，原业务更新器不能未经适配直接沿用其应用退出和文件替换行为。仅在没有进行中的查验任务时安装更新，安装前停止相关业务组件，完成后重新启动；更新失败保留可恢复的旧版本。首步只接入主屏，保留副屏现有业务行为，副屏暂不纳入统一显示校正。

若采用页面承载，代价是新增业务适配层及内容承载能力，不能直接导入业务主入口或只加载 HTML。具体接口、兼容检查和显示实现仍需设计与验证；初始接入行为以用户指定 release 为基线，业务源码和产物差异需核对，不能混用。独立业务工程输出接入产物，桌面读取该产物。

已确认运行边界：

- 首次进入查验时启动业务；返回桌面保留页面、后端和会话，再次进入继续操作。
- 已有独立业务程序运行并占用后端时提示先退出，不自动结束或接管该进程，也不同时启动第二个后端。
- “退出查验”关闭查验主副屏并停止本次启动的后端；退出整个桌面时也清理这些资源。存在进行中的查验任务时先确认，清理仅限自己启动的进程。
- 查验页面或后端异常时保持桌面可用，显示故障原因并提供重新连接或重启查验；涉及当前会话的重启由操作员确认。
- 指定目录缺少接入入口或接口版本不兼容时明确报错，不自动退回启动外部 EXE。

上述含长期目标，不代表全部功能或设备验证已完成。当前实现和未完成边界见 [接入说明](../inspection-integration.md)；更新安装及失败回滚、真实中文输入法、相机和双屏设备验收仍待后续验证。
